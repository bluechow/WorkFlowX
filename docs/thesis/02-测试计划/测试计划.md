## 2. 测试策略

### 2.1 功能测试策略

- **方法**：等价类划分 + 边界值分析 + 场景法 + 判定表
- **执行方式**：手动测试为主（验证 UI 交互与业务规则）
- **重点**：状态机全路径覆盖（30 种转换组合）、权限矩阵（3 角色 × 关键操作）

### 2.2 接口测试策略

- **方法**：黑盒测试——通过 HTTP 请求验证接口行为，不查看源代码
- **工具**：Python + pytest + httpx
- **重点**：状态码语义验证（200/201/400/401/403/404/409/422）、业务字段断言

### 2.3 UI 自动化策略

- **工具**：Playwright（真实浏览器驱动）
- **覆盖**：核心业务链路（登录→项目→工作项→流转→通知）
- **原则**：数据通过 API 准备（Setup via API），UI 只验证用户交互

### 2.4 性能测试策略

- **工具**：Python + httpx（模拟并发）+ 自定义指标采集
- **场景**：正常负载（10 并发）→ 峰值负载（50 并发）→ 极限测试（100 并发）
- **指标**：响应时间（P50/P95/P99）、吞吐量（TPS）、错误率

## 6. 风险与应对

| 风险 | 可能性 | 应对措施 |
|---|---|---|
| 环境不稳定（WSL/Docker） | 中 | 提前验证环境；准备环境重启脚本 |
| 需求理解偏差 | 低 | 需求分析文档经导师确认后执行 |
| 时间不足 | 中 | 优先执行 P0 用例；P2 用例可延后 |
