# 功能测试用例 — 权限控制（P0）

> 用例设计方法：**判定表**（3 角色 × 关键操作矩阵）
> 前置条件：系统中有 ADMIN、项目 OWNER、项目 MEMBER、非项目成员四种角色

## 权限矩阵（判定表）

| 操作 | ADMIN(系统管理员) | 项目OWNER | 项目MANAGER | 项目MEMBER | 非项目成员 | 未登录 |
|---|---|---|---|---|---|---|
| 查看工作项列表 | ✓ | ✓ | ✓ | ✓ | ✓(有权限码) | ✗401 |
| 创建工作项 | ✓ | ✓ | ✓ | ✗403 | ✗403 | ✗401 |
| 编辑工作项 | ✓ | ✓ | ✓ | ✗403 | ✗403 | ✗401 |
| 流转状态 | ✓ | ✓ | ✓ | ✗403 | ✗403 | ✗401 |
| 删除工作项 | ✗403(无删除权限码) | ✗403 | ✗403 | ✗403 | ✗403 | ✗401 |
| 管理项目成员 | ✓ | ✓ | ✓ | ✗403 | ✗403 | ✗401 |
| 管理用户(系统级) | ✓ | ✗403 | ✗403 | ✗403 | ✗403 | ✗401 |
| 查看审计日志 | ✓ | ✗403 | ✗403 | ✗403 | ✗403 | ✗401 |
| 踢下线用户 | ✓ | ✗403 | ✗403 | ✗403 | ✗403 | ✗401 |

---

## 用例

### TC-PRM-001：MEMBER 无创建权限

| 项 | 内容 |
|---|---|
| 用例编号 | TC-PRM-001 |
| 优先级 | P0 |
| 前置条件 | MEMBER 用户已登录且为目标项目成员 |
| 操作步骤 | 1. 打开项目工作项列表<br>2. 观察是否有「新建」按钮<br>3. 通过 API 直接 POST 创建请求 |
| 预期结果 | UI：无「新建」按钮<br>API：返回 403 + "permission denied" |

### TC-PRM-002：有权限码但非项目成员（数据级隔离）

| 项 | 内容 |
|---|---|
| 用例编号 | TC-PRM-002 |
| 优先级 | P0 |
| 前置条件 | ADMIN 用户有全部权限码但不是目标项目成员 |
| 操作步骤 | 通过 API 尝试在目标项目创建工作项 |
| 预期结果 | 返回 403 + "仅项目成员可操作"（数据级权限在 authority 之后拦截） |

### TC-PRM-003：未登录访问受保护接口

| 项 | 内容 |
|---|---|
| 用例编号 | TC-PRM-003 |
| 优先级 | P0 |
| 操作步骤 | 不带 Token 直接请求任意业务接口 |
| 预期结果 | 返回 401 + "authentication required" |

### TC-PRM-004：修改密码后旧 Token 失效

| 项 | 内容 |
|---|---|
| 用例编号 | TC-PRM-004 |
| 优先级 | P0 |
| 操作步骤 | 1. 用户 A 登录获得 Token1<br>2. 修改密码<br>3. 用 Token1 请求任意接口 |
| 预期结果 | 返回 401（旧 Token 已作废） |

### TC-PRM-005：同一账号二次登录顶掉旧会话

| 项 | 内容 |
|---|---|
| 用例编号 | TC-PRM-005 |
| 优先级 | P0 |
| 操作步骤 | 1. 浏览器 A 登录用户 U<br>2. 浏览器 B 也登录用户 U<br>3. 浏览器 A 刷新页面 |
| 预期结果 | 浏览器 A 被踢回登录页（Token 被覆盖） |

### TC-PRM-006：ADMIN 踢下线普通用户

| 项 | 内容 |
|---|---|
| 用例编号 | TC-PRM-006 |
| 优先级 | P1 |
| 操作步骤 | 1. 用户 B 登录<br>2. ADMIN 在「在线会话」页面踢 B 下线<br>3. B 刷新页面 |
| 预期结果 | B 被强制回登录页 |

### TC-PRM-007：ADMIN 不能踢自己

| 项 | 内容 |
|---|---|
| 用例编号 | TC-PRM-007 |
| 优先级 | P2 |
| 操作步骤 | ADMIN 尝试在在线会话页面踢自己下线 |
| 预期结果 | 按钮禁用 + API 返回 400 + "不能踢出自己的会话" |
