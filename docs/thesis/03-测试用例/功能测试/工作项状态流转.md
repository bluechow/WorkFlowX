# 功能测试用例 — 工作项状态流转（P0）

> 用例设计方法：**判定表 + 场景法**（六态状态机的全路径覆盖）
> 前置条件：已登录 ADMIN 账号且为目标项目成员；项目中已存在至少 1 个工作项

## 判定表：状态转换矩阵

| ↓当前状态 \ 目标状态→ | OPEN | IN_PROGRESS | RESOLVED | TESTING | CLOSED | REOPENED |
|---|---|---|---|---|---|---|
| **OPEN** | — | ✓合法 | ✗非法 | ✗非法 | ✗非法 | ✗非法 |
| **IN_PROGRESS** | ✗非法 | — | ✓合法 | ✗非法 | ✗非法 | ✗非法 |
| **RESOLVED** | ✗非法 | ✗非法 | — | ✓合法 | ✗非法 | ✗非法 |
| **TESTING** | ✗非法 | ✗非法 | ✗非法 | — | ✓合法 | ✓合法 |
| **CLOSED** | ✗非法 | ✗非法 | ✗非法 | ✗非法 | — | ✗非法 |
| **REOPENED** | ✗非法 | ✓合法 | ✗非法 | ✗非法 | ✗非法 | — |

合法流转 5 种 + 非法流转 25 种（含自身）= **30 种组合，全覆盖**

## 负向用例（非法流转，每种应被拒绝）

### TC-ITM-101~125：非法状态转换（参数化覆盖 25 种）

| 项 | 内容 |
|---|---|
| 用例编号 | TC-ITM-101 ~ TC-ITM-125（25 条参数化） |
| 优先级 | P0 |
| 前置条件 | 分别构造各状态的工作项 |
| 操作步骤 | 尝试通过 API 直接发起非法流转请求 |
| 预期结果 | **后端返回 HTTP 409（Conflict）**，错误信息包含「不允许的流转」；前端下拉不显示非法选项 |

**示例**：TC-ITM-101（OPEN → CLOSED）

```
请求: PATCH /api/v1/projects/{id}/issues/{issueId}/status
Body: {"fromStatus":"OPEN","toStatus":"CLOSED"}
预期: 409 + 错误信息
```

## 场景法用例（端到端业务链）

### TC-ITM-201：缺陷全生命周期（正常场景）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 创建 Bug（严重度 S2） | 编号自动分配，状态=待处理 |
| 2 | 分派给开发 | 开发收到分派通知 |
| 3 | 流转：待处理→处理中 | 状态变更，通知发送 |
| 4 | 流转：处理中→已解决 | 状态变更 |
| 5 | 流转：已解决→测试中 | 测试人员可看到 |
| 6 | 测试打回：测试中→重新打开 | 状态回退，开发收到通知 |
| 7 | 流转：重新打开→处理中 | 重新进入开发 |
| 8 | 流转：处理中→已解决→测试中 | 再次提测 |
| 9 | 流转：测试中→已关闭 | 终态 |
| 10 | 验证审计日志 | 以上每步均有 TRANSITION 记录 |

### TC-ITM-202：并发状态流转（竞争条件）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 两个用户同时打开同一工作项（状态=OPEN） | 均看到待处理 |
| 2 | 用户 A 先流转为处理中 | 成功 |
| 3 | 用户 B 随后尝试从 OPEN 流转 | 返回 409（状态已被 A 改变，B 的 fromStatus 过期） |
