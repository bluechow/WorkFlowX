# WorkFlowX 被测系统需求分析

> 本文档站在测试工程师视角，对被测系统 WorkFlowX 进行需求分析，作为后续测试计划与用例设计的依据。
> 被测系统版本：v2.1.0（GitHub: bluechow/WorkFlowX）

## 1. 系统概述

### 1.1 系统定位

WorkFlowX 是一个企业项目协作与工作项管理平台，面向中小型软件研发团队，覆盖从需求管理到测试交付的完整研发流程。

### 1.2 技术架构

| 层次 | 技术栈 |
|---|---|
| 前端 | Vue 3 + TypeScript + Element Plus + ECharts |
| 后端 | Java 21 + Spring Boot 3.5 + MyBatis-Plus |
| 数据库 | MySQL 8.0（业务数据）+ Redis 7.2（会话/缓存）+ MinIO（文件存储） |
| 部署 | Docker Compose 五容器编排（前端/后端/MySQL/Redis/MinIO） |

### 1.3 用户角色

| 角色 | 权限范围 | 典型操作 |
|---|---|---|
| 系统管理员（ADMIN） | 全部 59 项系统权限 | 用户管理、角色分配、在线会话管理、审计日志 |
| 项目管理者（MANAGER） | 项目内管理权限 | 项目设置、成员管理、里程碑管理 |
| 普通成员（MEMBER） | 项目内操作权限 | 创建/处理工作项、评论、上传附件 |

## 2. 功能需求清单

### 2.1 认证与用户管理

| 编号 | 功能 | 描述 | 优先级 |
|---|---|---|---|
| FR-AUTH-01 | 用户登录 | 用户名+密码登录，返回 JWT Token；密码错误 5 次锁定 | 高 |
| FR-AUTH-02 | 单会话控制 | 同一账号新登录使旧 Token 失效 | 高 |
| FR-AUTH-03 | 修改密码 | 验证旧密码后修改；修改后当前会话作废 | 高 |
| FR-AUTH-04 | 个人中心 | 修改昵称/邮箱；查看我的待办/工作项/项目 | 中 |
| FR-AUTH-05 | 在线会话管理 | ADMIN 查看全部在线用户；可远程踢下线 | 中 |

### 2.2 组织与团队

| 编号 | 功能 | 描述 | 优先级 |
|---|---|---|---|
| FR-ORG-01 | 组织 CRUD | 创建/编辑/删除组织；删除级联清理下属数据 | 高 |
| FR-ORG-02 | 部门管理 | 组织内部门树（多级）；增删改 | 中 |
| FR-ORG-03 | 组织成员 | 添加/移除成员；角色 OWNER/ADMIN/MEMBER | 高 |
| FR-ORG-04 | 用户角色分配 | ADMIN 可给用户分配/回收系统角色 | 高 |

### 2.3 项目管理

| 编号 | 功能 | 描述 | 优先级 |
|---|---|---|---|
| FR-PRJ-01 | 项目 CRUD | 创建（key 唯一）/编辑/归档/恢复 | 高 |
| FR-PRJ-02 | 项目成员 | 须先为组织成员才能加入项目；OWNER/MANAGER/MEMBER | 高 |
| FR-PRJ-03 | 项目概览 | 进度/状态分布/即将到期/最近动态 | 中 |
| FR-PRJ-04 | 里程碑 | 名称/目标日期/完成态；工作项归属里程碑 | 中 |

### 2.4 工作项管理（核心模块）

| 编号 | 功能 | 描述 | 优先级 |
|---|---|---|---|
| FR-ITM-01 | 工作项 CRUD | 四种类型（缺陷/任务/功能/优化）；项目内编号自动递增 | 高 |
| FR-ITM-02 | 状态流转 | 六态状态机：待处理→处理中→已解决→测试中→已关闭/重新打开 | 高 |
| FR-ITM-03 | 分派/取消分派 | 经办人须为项目成员；分派后通知经办人 | 高 |
| FR-ITM-04 | 标签管理 | 项目内标签 CRUD（名称+颜色）；工作项绑定多标签 | 中 |
| FR-ITM-05 | 工作项关联 | 相关/阻塞两种类型；同项目内；双向显示 | 中 |
| FR-ITM-06 | 截止日期 | 可设置/清空；逾期红色/临近橙色提示 | 中 |
| FR-ITM-07 | 看板视图 | 按状态分列；拖拽卡片即流转（走后端状态机校验） | 高 |
| FR-ITM-08 | 全局工作项视图 | 全部/我的/待我处理/我创建的四视图（跨项目） | 中 |

### 2.5 协作功能

| 编号 | 功能 | 描述 | 优先级 |
|---|---|---|---|

| FR-COL-02 | 附件 | 上传/下载/删除；类型白名单+10MB 上限 | 中 |

| FR-COL-04 | 活动流 | 项目级真实事件（创建/分派/流转/评论/附件/关联） | 中 |

## 3. 非功能需求

| 编号 | 类别 | 描述 |
|---|---|---|
| NFR-01 | 安全 | 59 项细粒度权限（RBAC）+ 数据级隔离（组织/项目双层） |
| NFR-02 | 安全 | JWT + Redis 单会话；密码 BCrypt 哈希；SQL 全参数绑定 |
| NFR-03 | 性能 | 核心接口响应 < 500ms（正常负载）；支持 50 并发用户 |
| NFR-04 | 可靠性 | 服务停止后数据不丢失（Docker 卷持久化）；优雅降级 |
| NFR-05 | 易用性 | 全中文界面；操作反馈即时（成功/失败提示） |

## 4. 测试重点识别

基于需求分析，以下为测试优先级最高的区域：

| 优先级 | 模块 | 原因 |
|---|---|---|
| P0 | 状态流转（FR-ITM-02） | 核心业务逻辑；六态状态机有严格合法/非法规则 |
| P0 | 权限控制（NFR-01） | 双层数据隔离是最重要的安全边界 |
| P0 | 认证（FR-AUTH-01~03） | 登录/会话/密码是系统入口 |
| P1 | 工作项 CRUD（FR-ITM-01） | 编号并发、字段校验、跨项目访问 |
| P1 | 测试计划执行（FR-TST-03） | 状态联动（NOT_STARTED 不可执行、COMPLETED 不可再加） |
| P2 | Excel 导入导出（FR-TST-02） | 边界值多（行数上限/单元格长度/枚举合法性） |
| P2 | 通知与@提及（FR-COL-03） | 触发条件复杂（排除自己/去重/跨类型） |

## 5. 测试约束

- 被测系统部署在本机 Docker 环境（localhost:8081）
- 数据库/Redis/MinIO 由 Docker Compose 统一编排
- 测试数据使用独立前缀（`qa_test_`），测试后自动清理
- 不修改被测系统源代码（黑盒测试原则）
