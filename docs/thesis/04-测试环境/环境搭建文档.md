# 测试环境搭建文档

> 本文档记录被测系统 WorkFlowX 的测试环境搭建过程，作为测试执行的前置条件。

## 1. 环境架构

```
┌────────────────────────────────────────────┐
│  测试人员浏览器                              │
│  http://localhost:8081                      │
└──────────────┬─────────────────────────────┘
               │
┌──────────────▼─────────────────────────────┐
│  Docker Compose（5 容器）                    │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐      │
│  │frontend │ │ backend │ │  mysql  │      │
│  │  :8081  │→│  :8080  │→│  :3306  │      │
│  └─────────┘ └────┬────┘ └─────────┘      │
```

## 2. 搭建步骤

### 2.1 前置条件

| 软件 | 版本 | 用途 |
|---|---|---|
| Docker Desktop / WSL Docker | ≥ 24.0 | 容器运行时 |
| Python | ≥ 3.11 | 测试脚本执行 |
| Node.js | ≥ 20 | 前端构建（可选，已有镜像则无需） |

### 2.2 部署被测系统

```bash
# 1. 克隆被测系统
git clone https://github.com/bluechow/WorkFlowX.git
cd WorkFlowX/deploy

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env 设置数据库密码、JWT 密钥

# 3. 一键启动全部服务
docker compose up -d

# 4. 等待全部容器健康（约 60 秒）
docker compose ps
# 预期：5 个容器全部显示 healthy
```

### 2.3 验证部署成功

```bash
# 健康检查
curl http://localhost:8081/api/v1/health
# 预期：{"status":"UP"}

# 登录验证
curl -X POST http://localhost:8081/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"demo_admin","password":"Demo@123456"}'
# 预期：200 + accessToken
```

### 2.4 初始化测试数据

被测系统内置演示数据包（`DEMO_SEED=true` 时自动生成）：
- 30 个测试用户（demo_admin / demo_pm / demo_u01~u28）
- 4 个项目（智慧校园 / 云帆电商 / 移动银行 / DevOps）
- 48 个工作项（覆盖全部状态/类型/优先级）
- 36 个测试用例 + 2 个测试计划
- 标签/关联/截止日期/里程碑/活动流/通知样本

## 4. 自动化测试环境

### 4.1 接口测试

```bash
# 安装依赖
pip install httpx pytest

# 运行测试
cd WorkFlowX
python -m pytest tests/api/ -v
```

### 4.2 UI 自动化

```bash
# 安装依赖
cd frontend && npm ci
npx playwright install chromium

# 运行测试
npx playwright test --workers=1
```

## 5. 环境重置

```bash
# 停止并删除数据卷（完全重置）
cd deploy
docker compose down -v
docker compose up -d
# 等待重新初始化（约 60 秒）
```

## 6. 已知环境限制

| 项 | 说明 |
|---|---|
| WSL 空闲回收 | Windows 环境下 WSL 约 60 秒无会话时回收容器（数据不丢，重启自动恢复） |
| 端口冲突 | 确保 8081/8080/3307/6379/9000 端口未被占用 |
| 网络代理 | 本机代理可能影响 Docker 拉取镜像 |
