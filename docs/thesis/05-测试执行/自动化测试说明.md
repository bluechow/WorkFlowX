# 自动化测试说明

> 本文档描述被测系统的自动化测试体系（开发方自带 + 测试方补充）及运行方法。

## 1. 测试体系总览

被测系统包含以下自动化测试线，按**测试主体**分为两类：

### 开发方测试（验证代码实现正确性）

| 测试线 | 工具 | 用例数 | 位置 | 运行命令 |
|---|---|---|---|---|
| 后端集成测试 | JUnit 5 + MockMvc + Spring Boot Test | 355 | `backend/src/test/` | `cd backend && mvn test` |
| 前端组件测试 | Vitest + @vue/test-utils + jsdom | 169 | `frontend/src/**/__tests__/` | `cd frontend && npm run test -- --run` |

### 测试方测试（验证系统满足用户需求）

| 测试线 | 工具 | 用例数 | 位置 | 运行命令 |
|---|---|---|---|---|
| API 接口测试 | Python + pytest + httpx | 179 | `tests/api/` | `cd tests && python -m pytest api/ -v` |
| UI 端到端测试 | Playwright + Chromium | 27 | `frontend/e2e/` | `cd frontend && npx playwright test --workers=1` |

## 2. 各测试线详细说明

### 2.1 后端集成测试（355 用例）

- **目的**：验证后端 Service/Controller 层的业务逻辑正确性
- **方式**：连真实 MySQL/Redis/MinIO；MockMvc 模拟 HTTP 请求
- **覆盖**：认证/用户/RBAC/组织/项目/工作项/状态机/标签/关联/评论/附件/通知/审计/仪表盘/活动流/里程碑/质量分析/测试用例/测试计划/全局搜索
- **特点**：
  - 数据级权限验证（403 场景）
  - 状态机非法流转验证（409 场景）
  - 并发编号不重复验证
  - Excel 导入资源上限验证（413 场景）

### 2.2 前端组件测试（169 用例）

- **目的**：验证 Vue 组件的渲染逻辑和交互行为
- **方式**：jsdom 模拟浏览器环境；mock API 层
- **覆盖**：登录/工作台/个人中心/全局工作项/项目/看板/工作项列表/角色/权限/用户/组织/审计/在线会话/测试用例
- **特点**：
  - 权限分支测试（有/无权限码的渲染差异）
  - 状态流转矩阵测试（合法/非法拖拽）
  - 搜索面板防抖/外部关闭

### 2.3 API 接口测试（179 用例）

- **目的**：以黑盒方式验证 REST API 的行为契约
- **方式**：真实 HTTP 请求（不 mock）；断言状态码 + 业务字段
- **覆盖**：认证安全/用户 CRUD/组织项目全链/工作项 CRUD+流转/评论附件/通知审计/测试管理/业务链
- **特点**：
  - 全部使用 `api_test_` 前缀动态用户（不污染种子数据）
  - 测试后自动清理（conftest.py 级联删除）
  - 单会话铁律：测试中不重复登录 seed 用户

### 2.4 UI 端到端测试（27 用例）

- **目的**：验证完整用户旅程（从登录到核心功能操作）
- **方式**：真实 Chromium 浏览器；API 准备数据 + UI 验证行为
- **覆盖**：登录/登出/核心模块（组织/项目/Issue）/通知/安全（XSS/权限）/测试用例/全链路
- **特点**：
  - storageState 复用登录态（避免重复登录）
  - Page Object 模式（e2e/pages/）
  - 串行执行（--workers=1）避免数据竞争

## 3. 运行环境要求

| 项 | 要求 |
|---|---|
| Java | 21+（Temurin） |
| Maven | 3.9+ |
| Node.js | 20+ |
| Python | 3.11+（pip install httpx pytest） |
| Docker | 运行中（开发基础设施：MySQL 3307 / Redis 6379 / MinIO 9000） |
| 被测系统 | http://localhost:8081 可访问（部署栈运行中） |

## 4. 测试数据管理

- **种子数据**：admin/user1 由 Flyway V2 迁移自动创建
- **演示数据**：demo_admin / demo_pm / demo_u01~u28 由 DemoDataSeeder 创建（DEMO_SEED=true）
- **测试数据**：所有测试使用动态前缀（api_test_），测试结束自动清理
- **清理机制**：conftest.py 的 session 级 fixture 在测试结束后级联删除测试创建的组织/用户/角色

## 5. 已知限制

- WSL 空闲回收可能导致测试环境短暂不可用（等待 30 秒自动恢复）
- Playwright 需要预先安装浏览器（`npx playwright install chromium`）
- API 测试依赖被测系统运行中（`deploy/docker-compose up -d`）
