## 1. 最终产品定位

**WorkFlowX —— 企业项目协作与工作项管理平台**
（Enterprise Project Collaboration & Work Item Management Platform）

核心价值链：组织管理 → 团队协作 → 项目管理 → 项目计划 → 工作项管理 → 任务分配 →
工作推进 → 项目跟踪 → 数据分析 → 项目审计。

不定位为：测试管理系统 / Jira 复制品 / Scrum 专用系统 / 微服务平台 / AI 平台。

### B. 必须增强（影响产品完整度，Final Edition 核心）
1. **导航与产品骨架**：当前是顶栏横排菜单（仅 ADMIN 可见系统菜单），MEMBER 登录后
   几乎无导航 → 必须改为应用级侧边栏 + 项目空间布局。这是「产品感」的最大缺口。
2. **工作台**：现在是统计型 Dashboard，缺 最近访问项目/最近动态/我的工作项视图/快捷操作。
3. **项目空间（概览）**：点进项目直接是 Issue 列表，无项目工作区（信息/成员/进度/动态/到期项）。
4. **工作项元数据**：无 标签、工作项关联、截止日期；无全局工作项视图（全部/我的/待我处理/我创建的）；筛选不高级。
5. **活动流（Activity Feed）**：完全缺失，项目动态无处可看。
6. **全局搜索**：无统一入口（项目/工作项/用户）。
7. **轻量计划**：无里程碑、无截止日期视图（Timeline/日历轻量实现）。

### C. 建议增强（轻量，顺手完成）
- 消息中心升级：全部/未读筛选已有，补「@我的」（评论 @提及 解析 → 通知）。
- 数据分析产品化：成员工作量（按经办人聚合）、Bug 专项统计页签。
- 看板快速创建卡片（列头 + 号，预填状态走正常创建流）。

### D. 不应该增加（防膨胀，明确排除）
Epic/Story Point/Burndown/完整 Scrum、WebSocket 实时、Email 服务、AI 任何形态、
微服务/K8s/Nacos/Kafka/Seata、在线编辑器、IM 聊天、**以及 B/C 之外的任何新业务模块**。

## 3. 最终信息架构（导航定稿）

```
左侧边栏（按权限渲染）
├── 工作台        /workspace          ← FP-5（替代 /dashboard 首页，旧路由重定向）
├── 项目          /projects           ← 项目列表 → 点击进入「项目空间」
├── 工作项        /work-items         ← FP-1 全局视图（全部/我的/待我处理/我创建的 + 高级搜索）
├── 数据分析      /analytics          ← FP-7
├── 消息中心      /notifications      ← FP-7 升级
├── 组织与团队    /team/*             ← 组织/部门/用户/角色/权限（ADMIN）
├── 系统管理      /system/*           ← 在线会话/审计日志（ADMIN）
└── 底部：个人中心 /profile、退出

项目空间 /projects/:id/…（页签式工作区）
├── 概览    /projects/:id/overview   ← FP-3（信息/成员/进度/统计/动态/即将到期/里程碑入口）
├── 工作项  /projects/:id/issues     ← 现有列表（增强筛选/标签/关联/截止日期）
├── 看板    /projects/:id/board      ← 现有（v1.2.0 已完成）
├── 计划    /projects/:id/plan       ← FP-4（里程碑/到期分组/简易时间线）
├── 动态    /projects/:id/activity   ← FP-2
├── 成员    /projects/:id/members    ← 从概览拆出或并入概览（轻量，并入概览）
└── 测试    /projects/:id/testcases|testplans ← §5 Q1 决策
```

「工作项（Work Item）」术语统一：界面导航/文案用「工作项」；API 路径、表名、枚举保持
`issue*`（契约稳定，零破坏）。类型四枚举不变。

## 5. 待确认决策

**Q1 测试模块（用例库/测试计划/Excel/报告页）去留**
现状：已存在且经完整 QA（v1.1.0/v1.2.0），是毕业设计测试方向的核心资产之一；
定版指令将其列入「不加入」清单。
- 方案一（推荐）：**保留并收进项目空间「测试」页签**，导航上一级不出现，停止扩展。
  理由：删除=破坏性变更（需 V20 drop 表、拆权限、删测试用例），违背 §九 Additive 原则；
  且它是你测试方向毕设的签名能力。
- 方案二：物理移除（回滚 V15/V16 能力，接受 QA 面收窄与演示数据重构）。

**Q2 最终版本号**
- v2.0.0（推荐）：产品形态完成（新 IA/新能力/封版），语义化版本以 major 标记里程碑；
- v1.3.0：严格按「纯增量不破坏」→ minor。

## 6. 角色权限（沿用，不新增权限码）

新能力全部挂靠现有权限：标签/关联/截止日期→`issue:update`；里程碑→`project:update`；
活动流读→项目读权限；搜索→`project:list`+`issue:list`+`user:list` 组合；
@提及通知→复用通知 self 资源。59 项系统权限数量冻结。

## 7. 已知限制（定版时如实声明）

- 通知为站内轮询，无 WebSocket/邮件（明确排除）；
- 计划为轻量里程碑+到期视图，非甘特/Scrum 工具；
- 单体架构，无微服务（ADR-001 维持）；
- 性能基线为开发环境小规模验证，未做生产级压测；
- 备份/恢复为文档化流程（deployment.md），未自动化。
